# Architecture

The existing monolith is retained: Express routes → controllers → services → Prisma repositories. Zod validates HTTP inputs. A JWT user identity scopes project/review operations and dashboard queries. The model output is parsed and validated separately from the request. React renders text via JSX; neither submitted code nor model output is executed or inserted as HTML.

## Code-review lifecycle

```mermaid
sequenceDiagram
  actor User
  participant UI as React UI
  participant API as Express API
  participant DB as PostgreSQL
  participant Model as Inference service
  User->>UI: Paste code or diff
  UI->>API: POST /api/reviews + bearer JWT
  API->>API: Authenticate and validate input
  API->>DB: Find project owned by user
  API->>DB: Create ANALYZING review with input
  API->>Model: Prompt + configured model + JSON schema
  alt Valid completion
    Model-->>API: JSON summary and findings
    API->>API: Validate findings and calculate score
    API->>DB: Transaction: store findings and COMPLETED state
  else Unavailable, busy, timeout or invalid output
    API->>DB: FAILED state and safe error message
  end
  API-->>UI: 201 with persisted review (COMPLETED or FAILED)
  UI->>API: Refresh review history and dashboard
  UI-->>User: Findings or failure explanation
```

## Inference and generation

```mermaid
flowchart LR
  Input[Untrusted code text] --> Normalize[DiffService normalization]
  Normalize --> Prompt[ReviewPromptService]
  Prompt --> Admission[Per-process concurrency admission]
  Admission --> Request[Chat-completion request with JSON schema]
  Request --> Server[vLLM + tokenizer chat template + model]
  Server --> Bound[Timeout and response-byte limit]
  Bound --> Parse[JSON extraction / parsing]
  Parse --> Zod[Finding and line-range validation]
  Zod --> Score[Backend severity scoring]
  Score --> Persist[Prisma review completion]
  Bound --> Failure[Safe error / failed review]
  Parse --> Failure
  Zod --> Failure
```

The HTTP schema constrains summary and findings. Optional fields not generated by the serving schema retain Zod/database defaults. The backend ignores model-supplied scores and calculates its own. The code prompt still uses the original user-message structure; prompt injection remains a model-quality boundary, mitigated by keeping output as untrusted text and avoiding tools/code execution.

## Database

```mermaid
erDiagram
  User ||--o{ Project : owns
  User ||--o{ Review : creates
  Project ||--o{ Review : contains
  Review ||--o{ ReviewFinding : contains
  User {
    string id PK
    string email UK
    string passwordHash
  }
  Project {
    string id PK
    string ownerId FK
    string name
  }
  Review {
    string id PK
    string userId FK
    string projectId FK
    string inputContent
    enum status
    int score
  }
  ReviewFinding {
    string id PK
    string reviewId FK
    enum severity
    enum category
    string description
  }
```

Project/review deletes cascade to findings; deleting an account at the database level cascades its projects/reviews. No account-deletion HTTP route exists. Review completion stores findings transactionally. Dashboard raw SQL uses Prisma parameter bindings. The initial migration is retained and must be applied using `prisma migrate deploy`.
